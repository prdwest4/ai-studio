# AI STUDIO — MASTER SPECIFICATION

نسخه: MVP / Product Creation Engine

1. هدف اصلی

---

هدف پروژه ساخت یک پلتفرم واقعی AI Studio است که کاربر در آن به جای انتخاب مدل، Provider یا ابزار، فقط محصول موردنظر خود را توضیح دهد.

نمونه:

«برای فروشگاه لباس من یک تیزر تبلیغاتی ۲۰ ثانیه‌ای بساز.»

سیستم باید بتواند:

* درخواست کاربر را بفهمد.
* Product Brief ایجاد کند.
* کار را به مراحل لازم تقسیم کند.
* ابزارهای مناسب را پیدا کند.
* ابزار مناسب را انتخاب کند.
* محتوا تولید کند.
* خروجی‌ها را مدیریت کند.
* ویدئو و صدا را ترکیب و تدوین کند.
* کیفیت خروجی را بررسی کند.
* در صورت خطا Retry یا Repair انجام دهد.
* خروجی نهایی را تحویل دهد.

اصل اصلی:

PRODUCT FIRST

محصول هدف است؛
Model، Provider، API، Website، Browser، Software و Local Tool فقط ابزار هستند.

2. استقلال از Model و Provider

---

سیستم نباید به یک Model یا Provider خاص وابسته باشد.

کاربر نباید مجبور باشد:

* Model انتخاب کند.
* Provider انتخاب کند.
* Model ID بداند.
* Endpoint بداند.
* Adapter فنی انتخاب کند.

سیستم باید در پشت صحنه بهترین ابزار در دسترس را برای کار موردنظر پیدا و انتخاب کند.

3. API تنها روش اتصال نیست

---

ابزارها می‌توانند از روش‌های مختلف متصل شوند:

* API
* Web API
* Browser
* Local CLI
* Local Software
* File-based Tool
* MCP / Agent Tool

ابزار لازم نیست حتماً API داشته باشد.

هدف استفاده از هر ابزار قانونی و قابل اتکایی است که بتواند بخشی از محصول را تولید کند.

6. MVP

---

MVP باید ابتدا فقط یک مسیر End-to-End واقعی داشته باشد.

سناریوی اصلی:

«برای فروشگاه لباس یک تیزر تبلیغاتی ۲۰ ثانیه‌ای بساز.»

سیستم باید واقعاً:

* Brief بسازد.
* برنامه تولید ایجاد کند.
* ابزارهای لازم را پیدا کند.
* Asset تولید کند.
* Video تولید کند.
* Voice/Music در صورت نیاز ایجاد کند.
* Media را تدوین کند.
* QC انجام دهد.
* خروجی واقعی MP4 تحویل دهد.

Mock نباید جای قابلیت اصلی را بگیرد.

9. امنیت

10. مدیریت هزینه

---

برای هر اجرای واقعی باید هزینه کنترل شود.

سیستم باید بتواند:

* هزینه تخمینی را محاسبه کند.
* هزینه واقعی را ثبت کند.
* سقف هزینه داشته باشد.
* در صورت عبور از سقف، اجرا را متوقف کند یا تأیید کاربر بگیرد.

11. Storage

---

MVP از SQLite استفاده کند.

Storage باید با Repository/Abstraction طراحی شود تا در آینده امکان مهاجرت به PostgreSQL وجود داشته باشد.
